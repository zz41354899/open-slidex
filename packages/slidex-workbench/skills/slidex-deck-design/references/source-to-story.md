# Source to story

Use this reference to transform raw input without losing meaning or inventing
evidence.

## Start with a source brief

Record these before outlining slides:

- Audience: who will see this, and what do they already know?
- Outcome: what should they understand, decide, believe, or do?
- Evidence: which claims are directly supported by the source?
- Constraints: language, slide count, brand, timing, required sections.
- Gaps: what is unknown, ambiguous, outdated, or contradictory?
- Thesis: one sentence the deck must make memorable.

## Input modes

### User prompt

Extract audience, outcome, topic, tone, and constraints. Make only reversible
design assumptions. If facts are missing, build a structural draft and label
evidence gaps; do not fabricate supporting claims.

### Notes or bullet list

Cluster related points, remove duplicates, and separate observations from
decisions and actions. Preserve distinctive wording only when it is intentional.
Do not give every bullet equal visual weight or one slide of its own.

### Document

Find the thesis, strongest sections, evidence, examples, and final implication.
Recompose for presentation reading order; do not reproduce the table of contents
or create one slide per heading. Compress background and promote conclusions.

### Research report

Keep method, finding, interpretation, limitation, and recommendation distinct.
Preserve dates, denominators, units, uncertainty, and attribution. Build charts
only from explicit values. A limitation that changes the conclusion belongs in
the main story, not hidden in fine print.

### Dataset or spreadsheet

Check units, missing values, time periods, category definitions, and denominator
before charting. Identify one decision-relevant pattern per visual. Keep exact
lookup values in a table when aggregation would mislead.

### Existing deck

First inventory claims, evidence, slide roles, repeated layouts, broken assets,
and unsupported tags. Preserve supported facts and user-owned content while
rebuilding the narrative and composition. Redesign is not permission to rewrite
the meaning.

## Evidence map

For each proposed slide, write `claim -> support -> implication`. Drop a slide
if its claim does not advance the thesis. Mark unsupported claims as `gap`, and
keep citations or source labels close to the evidence they support.
